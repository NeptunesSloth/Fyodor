# Cross-recipient prevention: isolated joint frontier proof

Current status: VERIFIED batch 43. The reviewed joint bridge and five exact card recipes are live; see `cross-recipient-prevention-cards.md` for accepted production evidence. The dated development stages below retain the sequence of isolated proofs. The existing single-recipient allocator and unsupported finite-effect ownership guard remain intact.

The immutable JSON frontier retains the original batch and source/recipient identities, affected-player local replacement traces, allocation-controller pool ownership, source-per-batch versus turn-remainder scope, approved vectors and redirect child lineages. Each child's inherited candidate IDs prevent reapplication under 614.5. Redirected damage retains the original source, including when two pools return it to its original recipient. A destination has its own affected-player trace.

For every local pool row, the model derives a capacity expression from earlier operations on that specific packet. The pool has one global equation:

`sum(allocation rows) = min(remaining budget, sum(eligible local capacities))`.

Opposite local A/B orders are a system of simultaneous constraints, rather than an instruction to apply either pool globally first. A two-packet proof admits interior vectors A=(1,2), B=(2,1). The redirect proof also rejects allocations that depend entirely on nonexistent child damage from the other pool. Switching packet traversal or allocation-selection order does not change the feasible outcomes.

The first module is an exhaustive reference oracle for small cases. The second derives affine integer constraints: each allocation is between zero and its capacity, each pool is bounded by both its budget and total capacity, and one of those upper bounds is an equality. Integer interval propagation and binary branching find one feasible completion of a numeric prefix, without enumerating every vector. It rejects fractional-only answers and handles the billion-damage proof. The solver is still a prototype; this establishes representability, not a production performance guarantee.

Thirteen frontier tests cover cyclic prevention and redirection, controller entitlement, cold JSON, local multiplier order, protection, unpreventable prevention versus redirection, per-source budgets, original OID, zero and insufficient budgets, stale choices and dependency-only invalidation. Six constraint tests compare every small numeric prefix and every complete reference solution against the exhaustive oracle, plus large counts and invalid constraints. All nineteen passed.

## Native bridge proposed for review

The live bridge must be a separate opt-in batch-budget path. It must snapshot candidates and retain the ordinary source metadata, full matching descriptors, original caller terminal and receipt/rider continuation ownership. It must not feed a provisional greedy allocation to `Planner._by_first` to conclude that effects commute.

At each local replacement frontier, the affected player owns the native 616 choice. Crossing into a redirected recipient changes the affected chooser and recomputes candidate applicability; it does not erase inherited applied IDs. The pool's printed controller separately owns numeric allocations across all eligible source/recipient lineage rows. Saved numeric prefixes can be checked for a joint completion by the integer solver, before any damage or shield consumption commits.

Each selected vector must then be grounded through the ordinary native replacement operations, preserving prevention receipts, immediate rider source snapshots, actual damage traits, native protection and all final damage-result replacements. The remaining pool balance is committed once. A changed earlier frontier invalidates its vector and capacity descendants; cycles invalidate their dependent component, while unrelated approved vectors remain.

The present proof model takes already-chosen local traces and a bounded operation vocabulary (integer multipliers, full protection, finite prevention and finite redirect). It does not yet discover native choice frontiers, preserve all native match predicates, model amount-dependent applicability or optional replacement choices, or execute final damage results. A native adapter must represent those semantics explicitly; unsupported operations must keep the entire affected printed-card path gated. No current proof justifies removing a guard or silently ignoring an interfering candidate.

Before card hooks, required native cases remain Earthquake/Pyroclasm 1+1 splits, Cover's trample/blocker/player and independent-source budgets, different allocation/affected players, local Furnace/protection order, unpreventable damage, opposite pools with different controllers, old/new OID and source LKI, cold partial vectors and 616 decisions, exact committed receipts, and deterministic replay.
