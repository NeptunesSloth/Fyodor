### B. Actual evolve outcome event (Watchful Radstag)

Existing keyword_triggers generates evolve's intervening-if condition and ordinary +1/+1 counter instruction, but there is no `evolves` event. Official ruling: evolves only when that evolve ability resolves AND puts one or more +1/+1 counters; doubling still produces ONE evolves occurrence; arbitrary counters never count; no counter due to replacement/gone source means no occurrence.

Add a typed event emitted only by the native evolve keyword resolution after its queued counter instruction completes, based on the exact original source OID and actual positive counter-put outcome. Reuse the existing counter receipt/batch events, not net counter totals (opposing -1/-1 counters/SBA cancellation must not erase the fact a +1/+1 counter was put). Preserve an optional callback/marker through native616 pauses and cold loading. Add small event-kind/parser/collector hook for `~ evolves`. Native entered-creature comparison and resolution recheck remain unchanged. Token copy uses self current/LKI; copied Radstag has evolve and can reproduce, with counters excluded from copied base values. No ordinary counter action synthesizes an evolves event.

### C. Genuine embalm creation provenance for conditional copy entry (Vizier)

Native graveyard_keywords already builds embalm as an activated GY-exile cost plus ordinary token_copy with white/Zombie/no-mana exceptions. Vizier's conditional entry needs actual embalm provenance; merely guessing from white/Zombie/no-mana exceptions is unsound because another copy effect can independently produce those traits.

Prefer an existing native token-creation origin receipt if inspection finds one. Otherwise add an optional defaultFalse noncopiable `embalmed` creation/entry receipt supplied ONLY by native embalm keyword resolution and carried through token replacement/entry-choice snapshots. It must be available while prospective Vizier entry chooses its copy, and it must not propagate when an unrelated later effect copies that token. Do not put the designation into a normally copied CopyRecipe flag. Apply Vizier's three copiable exceptions after selecting the new copy recipe only when this receipt is true. An ordinary Vizier/Clone entering as a copy of an embalmed token is not itself embalmed; a second-generation copy inherits copiable white/Zombie/no-mana values through its copied recipe, not the provenance flag. Declining to copy an embalmed Vizier still creates its native white Zombie0/0 which dies normally. Native embalm mana/GY-exile/sorcery timing/ability loss remain authoritative.

### D. Linked card belongs to created Spirit's granted leave ability (Hofri)

Native exact `exiled_with` registry already supports per-source-incarnation groups. Hofri must copy the original BF recipe (official ruling), while exiling the exact current post-death GY card first. Failure to exile means no token. After one native creation batch, associate each actual Spirit copy carrying the granted leave ability with ONLY that instruction's exact newly-exiled card OID, keyed by that token's own sourceOID. Parallel-created Spirits all refer to the same one original card; the first departure returns it; later departures cannot follow a re-exiled new incarnation. A later independent copy of the Spirit inherits the printed trigger text but no link registry entry, so returns nothing (official ruling). Source Hofri leaving/control changing must not break existing links.

Use a bounded explicit granted linked-return definition if native `_link` assumes the exile instruction must be on the same permanent; printed607 linking here intentionally grants the second ability to another object. Do not relax arbitrary unlinked references globally. No opaque card IDs in quoted text or copiable names. Additional replacement Food/Angel outputs only acquire a link if they actually have that granted ability; do not guess all outputs have the copied exception.
