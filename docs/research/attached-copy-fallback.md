# Springheart Nantuko and Crafty Cutpurse

Springheart Nantuko's [official rulings](https://api.scryfall.com/cards/54a3ea87-005e-4985-b2a5-21711d0b71c0/rulings) confirm that declining the payment, being unable to pay, or not being attached to a creature you control still creates the ordinary Insect. Its ability uses the original trigger controller for "you," even if Nantuko itself changes controller before resolution. Resolve the source by its captured object ID: a new bestowed object of the same physical card cannot supply the old trigger's host.

The typed effect sequence prepares a live attached host reference and eligibility flag, gates the existing optional-payment primitive, invokes the native token-copy pipeline when paid, and creates an Insect only if the copy instruction did not actually create a token **by that player**. A replacement making Angels still creates tokens and suppresses the fallback. Doubling the copies also suppresses it. The copy uses copiable values, so Nantuko's +1/+1 bonus to its host is not copied. The host reference retains last-known copiable information if the host is sacrificed to a mana ability while the optional payment is pending. State-based actions, including unbestowing the now-unattached Nantuko, wait until the resolution finishes.

Crafty Cutpurse's [official rulings](https://api.scryfall.com/cards/117d84f7-45c5-4cfc-a5cd-c44416b48417/rulings) require its control-changing token replacement to be applied **before** token multipliers. CR 616.1a–b puts self-replacements first and then replacement effects modifying under whose control an object enters; only after these do ordinary applicable replacements compete (616.1e–f). The shared replacement planner now gives the new token-creation-controller operation this priority. Consequently the original would-be controller's Doubling Season does not apply after Cutpurse takes the event; the new creator's Season does apply. No choice allows the original player to double first.

Multiple Cutpurse effects compete within this priority class. The would-be token controller chooses the first, the new would-be controller chooses among remaining applicable effects, and each applies only once. Tests with two other players' Cutpurses verify that the last applicable effect determines the eventual creator and that each replacement is used once on each creation event. A resolved Cutpurse effect lasts for the turn independently of its source remaining on the battlefield.

The distinction from a mere entry-control replacement matters. Cutpurse's current Oracle explicitly replaces **creation under a controller**, rather than simply changing control as an otherwise-created object enters (as Gather Specimens does). Under CR 614.6 the original creation event does not happen; the modified creation event does. CR 111.2 identifies the creator as the token's owner and creation/entry controller. Thus the modified creation is by Cutpurse's controller. When Nantuko's copy is created this way, its original controller did not create that token, so the fallback Insect is also attempted—and can itself be taken by Cutpurse. The root agent independently checked this rule interpretation before the checkpoint. Creation bindings retain actual resulting token objects, and the predicate checks their token status and ownership, falling back to snapshots if necessary.

Verification: 24 focused cases cover paid copy, decline, insufficient resources, unattached source, host departure/control changes, source control changes, source departure/phasing, an actual Alchemist's Refuge-enabled recast into a new bestowed object before the old trigger resolves, replacement-created Angels and doubled copies, source-independent/end-of-turn Cutpurse duration, own-controller exclusion, creator priority with either player's multiplier, multiple competing Cutpurses, and actual Phyrexian Altar sacrifice during a payment. All gameplay choices check replay and JSON save/load. A direct empty-creation-binding test covers the fallback predicate's zero-token result.

The 24 focused cases plus 25 existing token, nested-payment, and bestow regression cases pass together (49 total). Seven older nested-mana assertions were updated to the aggregate `mana_pool` helper because the shared mana engine now retains source-aware mana units; production payment behavior was not changed for those assertions. Fourteen canonical fixture records include complete colors, identity, mana value, keyword, layout, power/toughness, and face metadata.

Dependency boundary: token-entry prohibitions such as Worms of the Earth's "Lands can't enter" and Hallowed Moonlight remain unsupported elsewhere. This change does not falsely treat them as automated test fixtures or implement those broader mechanics. It verifies an empty actual-creation binding directly, so future shared creation-prevention support will naturally take Nantuko's fallback path.
