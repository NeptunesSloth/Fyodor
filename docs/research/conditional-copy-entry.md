# Conditional exceptions while entering as a copy

Canonical Oracle is in `tests/fixtures/conditional_copy_entry_cards.json`. The implementation uses the stored Comprehensive Rules dated 2026-09-25, particularly 614.12 (entry replacement evaluation), 707.5 (entering as a copy), 707.9a (copiable ability exceptions), 707.9e (additional noncopiable entry effects), 707.9f (conditions on the resulting copy), and 702.63 (vanishing).

Flesh Duplicate's exception explicitly asks whether **that creature**, the selected original, has vanishing. This differs from an exception conditioned on the resulting copy's characteristics. It reads the selected source's current ability records when the copy replacement applies, including granted abilities and ability loss. If the source lacks vanishing, the replacement adds Vanishing3 as an ordinary copiable exception; subsequent copies therefore also have it and enter with their own three time counters. If the source has any vanishing ability, no additional instance is added and existing counters are never copied.

An actual Soultether Golem under Turn to Frog has no vanishing, so Flesh Duplicate copies its printed Vanishing1 and additionally gains Vanishing3. It enters with four time counters. Conversely, an actual Maelstrom Djinn turned face up has noncopiable granted bare Vanishing; this suppresses the extra3, while the grant is not copied, so Flesh Duplicate enters as a plain Djinn without vanishing or time counters. Scryfall's Flesh Duplicate rulings list was empty when checked; these edges follow the explicit Oracle antecedent and the distinction from 707.9f's copy-self conditions.

Undercover Operative's shield is an additional entry effect under 707.9e, not an ability added to the copied values. It is supplied to the normal entry-counter pipeline if the selected original was controlled by the entering copy's controller when the copy replacement applied. Physical ownership is irrelevant. Later copies do not inherit the shield counter or a shield-entry instruction.

An entering copy effect now optionally records its selected source's card ID, exact object ID and controller. The existing copy recipe and that source snapshot are reused through later entry/replacement-order questions instead of being rebuilt from a possibly changed source. This metadata belongs to the entering continuous effect, outside CopyRecipe, and old saves default to no metadata. A saved Undercover entry-order prompt retains its initial shield eligibility even if the source changes controller before the answer.

The Maelstrom Djinn case also adds native support for granting bare Vanishing permanently. It grants the two existing vanishing triggers and no entry-counter replacement. Under Solemnity, the Djinn receives no time counters but still gains vanishing; at its upkeep it does not sacrifice itself because no last counter was removed. A later genuine last-counter removal does trigger sacrifice.

The tests cover canonical casts and morph costs, copying/declining, numbered and granted/lost vanishing, normal copies of copies, ownership versus control, native counter doubling and replacement-order pauses, real upkeep/last-counter sacrifice, JSON/history replay and a saved entry-order question resumed in a fresh process.
