# Isolated ordinary-turn producer proposal; not a shared patch approval request yet

Inspection: engine.start_next_turn presently selects restrictions, exerted/next-untap, skip, phasing, may-stay and limits, then classifies stun before NextTurn auto-untaps ordinary objects. untap_choice.resume/_limits directly untap their permitted held objects and dispatch finish_turn_start. finish_turn_start removes stun, handles duration/day-night/mana riders, other-player untap riders, advances upkeep. extra_untap_step duplicates the classification. Therefore a hook only at finish_turn_start is too late: normal auto-untap and choice resumptions may already have committed the original event.

Proposed bounded interfaces, after native capture approval:

1. NativeBatch holds original recipient refs, actual step player, origin enum own_turn/extra_own_step/other_player_step/effect/cost, and original granter snapshot per attempt. Its final continuation is typed TurnFinish or exact effect context, never a synthetic default finisher. NativeGrant must retain source ref + source ability index + static branch path + declared ordinal + native expansion path; rendered holder positions do not participate.

2. prepare(plan, player, already_kept, may_stay, limited) is pure capture/classification. Called only after skip/phasing/restriction computation and before existing stun classification/NextTurn. It returns original held refs and captured eligible origins, without removals or untapping. All originally normal keep/may-stay/limited membership remains separate: a replacement-held object still participates in the existing may-stay/limit eligibility as though not held. Unknown matching quote origins cause explicit unsupported failure before NextTurn mutation; no silent omission.

3. Existing native may-stay/limit choice order remains. Their result callback yields permitted exact original refs to the batch instead of immediately untapping only those intercepted refs. Unintercepted refs keep the old direct path. A permitted replacement-held object then creates its attempt; choosing to stay tapped/being denied makes no attempt and preserves counters. Stun classification must exclude intercepted refs so model owns the competing stun replacement exactly once.

4. drain(plan,batch) applies the native affected-controller 616 choice per original pending attempt, saves the entire typed batch/continuation before any decision, and seals effect ancestry before actual native removal. Native source changes during a saved choice require recapture of currently applicable exact origins; an original applied effect remains in ancestry, while a truly new eligible source OID is distinct. Unknown matching origins must fail explicitly; restarting attempt ancestry is forbidden. Discovery and scheduling of simultaneous multi-controller recipients needs separate CR101.4/616 proof; not assumed from state iteration order.

5. finish(batch) marks completion once, calls the original native turn finisher with intercepted refs excluded from legacy stun-removal and retried untap, while retaining their original refs in the held set. No change to default no-interception fast path. Administrative stale refs never bind successors. All choices must save actual M/Pydantic refs rather than naked card IDs.

Proof gates before shared diff: may-stay both choices with Leech+stun; one-creature limits selecting/denying intercepted object; exert/next-step holds; skipped own step; phasing in/out of original Aura/holder; extra own untap step; auto_untap on/off; two recipients with actual joint replacement-order authority; native saved finisher once and no priority before upkeep; new Aura becomes applicable during saved choice; quote-source wipe and unknown resolved grant; true cold each decision/after first real counter removal. Other-player Seedborn and untap costs require their own origin paths; own-step Leech never applies there. No whole-card Leech claim until complete paths proved.

No shared engine/choice/turn/schema edits made. This documents concrete mutation boundaries and remaining order gates rather than claiming a finished scheduler.

Bounded-scope refinement: exact Leech own-step quote only applies to holders controlled by that step's player. Thus a bounded ordinary/extra-own-step producer has one affected controller; CR101.4c lets that player choose outstanding same-time choice order, while616.1/616.1f requires per-attempt effect re-evaluation. CR616.1g contains the Leech-produced untap within replacement of the original untap, so its effects cannot be selected before the outer Leech replacement; model ancestry persists. Native other-player Seedborn untaps do not satisfy the quote's own-step condition and must retain ordinary stun behavior. A generalized simultaneous multi-controller scheduler remains a separate foundation gate, not necessarily a blocker for the exact own-step quote. No per-recipient dict-order choice is justified by this refinement.

Commit boundary still to prove before implementation: existing single-attempt model commits terminal native untap immediately. A batched ordinary-step producer must distinguish original simultaneous untap events from native side effects/contained untap generated by Leech replacements. It must not expose an arbitrary preview untap of another pending recipient while choosing replacements. Existing model.finish cannot be reused once per recipient because that would advance upkeep multiple times; batch owns one final continuation and per-attempt model execution must omit its individual finisher. This needs an explicit per-terminal result callback or batch-owned drain rather than inventing a fake effects context. Native normal recipient untaps should remain one actual untap action after relevant choices, unless a contained replacement event expressly requires its own action. Current proposal does not claim these commit semantics solved.
